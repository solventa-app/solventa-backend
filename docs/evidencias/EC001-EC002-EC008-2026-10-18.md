# Evidencia EC001, EC002 y EC008 — API Gateway y presupuesto por dependencia (HA-LAT-004)

- **Fecha:** 2026-10-18
- **Historia de arquitectura:** HA-LAT-004 (API Gateway delante del BFF con timeout duro de 700 ms y presupuesto ≤ 120 ms por dependencia en el ACL Worker)
- **Escenarios:**
  - **EC001 / EC002:** latencia extremo a extremo a través del API Gateway con **p99 ≤ 500 ms** en operación con caché/proveedores sanos.
  - **EC008:** presupuesto de tiempo **≤ 120 ms por dependencia** en el ACL Worker (`PRESUPUESTO_MS_*`) y **corte duro de 700 ms** (`deadline: 0.7` en `openapi.yaml` / `timeout: 0.7s` en `envoy.yaml`).
- **Guion ejecutado:** [`tests/k6/gateway-presupuesto.js`](../../tests/k6/gateway-presupuesto.js) y validador [`scripts/validar_gateway.py`](../../scripts/validar_gateway.py)

## 4. Arquitectura verificada (Bloque 10)

1. **BFF privado en Cloud Run:** se retiró `"publico": true` del BFF en `.github/servicios.json` (validado en CI por `scripts/validar_servicios.py`). Solo la cuenta de servicio `gateway-bff` (`infra/gateway.tf`) posee `roles/run.invoker` sobre el BFF.
2. **Propagación de JWT de usuario (decisión 17):** como ESPv2 en GCP API Gateway reemplaza `Authorization` por su token OIDC de `gateway-bff` y mueve el JWT del usuario a `X-Forwarded-Authorization`, el BFF (`services/bff/app/autenticacion_usuarios.py`) lee `X-Forwarded-Authorization` cuando está presente y cae a `Authorization` en local/Envoy.
3. **Presupuesto por proveedor en ACL Worker:** `services/acl-worker/app/application/configuracion.py` define un presupuesto de 120 ms por proveedor (`PRESUPUESTO_MS_*`), permitiendo que las 5 fuentes consultadas en paralelo degraden a caché mucho antes de alcanzar el deadline duro de 700 ms del API Gateway.
